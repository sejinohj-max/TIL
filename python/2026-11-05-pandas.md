## 오늘 배운 것

- **Series vs DataFrame**: 시리즈는 열 하나(1차원), 데이터프레임은 표 전체(2차원). `df['age']`는 시리즈, `df[['age']]`는 1열짜리 표.
- **데이터 살펴보기**: `head` / `tail` / `shape` / `info` / `describe` / `dtypes`
- **찾아가기**: `loc`은 이름표로, `iloc`은 위치 번호로. `loc[행, 열]`은 쉼표 앞이 항상 행, 뒤가 항상 열.
- **지우기**: `drop(axis=0)`은 행, `drop(axis=1)`은 열. `index=` / `columns=`로 쓰면 안 헷갈림. drop은 새 표를 돌려줘서 원본은 그대로임.
- **불 인덱스**: 조건으로 True/False 목록(마스크)을 만들고, True인 행만 남김. 조건 연결은 `&` / `|` / `~`를 쓰고, 조건마다 괄호를 침.
- **groupby**: 나누기 → 계산하기 → 합치기. 기준 열은 결과에서 인덱스로 올라감. `reset_index()`나 `as_index=False`를 쓰면 SQL처럼 평평한 표가 됨.
- **MultiIndex / unstack / pivot_table**: 기준이 두 개면 2층 이름표가 됨. `unstack()`으로 펼치면 교차표가 됨.

## 판다스 ↔ SQL 핵심

| 하고 싶은 일 | 판다스 | SQL |
|---|---|---|
| 열 고르기 | `df[['a', 'b']]` | `SELECT a, b` |
| 행 거르기 | `df[df['age'] > 30]` | `WHERE age > 30` |
| 묶어서 계산 | `groupby('pclass')['fare'].mean()` | `GROUP BY pclass` + `AVG(fare)` |
| 묶은 뒤 거르기 | `r[r > 20]` | `HAVING AVG(fare) > 20` |
| 행 개수 / 값 개수 | `size()` / `count()` | `COUNT(*)` / `COUNT(열)` |
| 정렬 + 자르기 | `sort_values(...).head(3)` | `ORDER BY ... LIMIT 3` |
| 위치로 찾기 | `iloc[2]` | 없음 (SQL 표엔 고정된 순서가 없음) |

## 돌아보기

**제일 헷갈렸던 것: 괄호**
`df.drop([0, 2])`를 처음엔 "0행 2열 칸 하나"로 읽었다. 괄호 모양은 "좌표냐, 목록이냐"만 알려주고, 그게 행인지 열인지 값인지는 함수와 `index=` / `columns=`가 정한다는 걸 알고 나서 정리가 됐다. 리스트는 방향 없는 봉투다.

**새로 보인 것: "열은 이름으로, 행은 조건으로"**
번역표를 보다가 판다스도 SQL도 거의 다 열 이름으로 돌아간다는 게 눈에 들어왔다. 열은 수가 적고 뜻이 있어서 이름으로 부르고, 행은 많아서 조건으로 거른다. SQL이 SELECT(열)와 WHERE(행)로 자리를 나눈 이유가 이거였다.

**SQL이랑 같이 배우니 좋은 점**
WHERE에서 평균을 못 쓰는 이유를 실행 순서(FROM → WHERE → GROUP BY → HAVING)로 이해했다. 판다스는 쓴 순서대로 실행되니까 같은 흐름이 코드에 그대로 보인다. 반대로 groupby 결과에서 `r['pclass']`가 에러 나는 것처럼, SQL 습관대로 생각하면 틀리는 지점도 분명히 있다.

**나만의 확인법**
헷갈리면 조건마다 True/False를 따로 찍어보고, `shape`를 원본과 비교해 본다. OR 조건에서 요금이 안 넘는 2살 아이가 뽑혀서 버그인 줄 알았는데, 조건별로 찍어보니 바로 이해됐다.
