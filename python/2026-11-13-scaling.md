## 오늘 배운 것 (요약)

- **스케일링** = 단위와 범위가 다른 속성들을 같은 기준으로 맞추는 전처리. 거리 기반 모델(KNN, K-means, SVM)에는 필수이고, 선형 모델·신경망은 학습이 안정적이고 빨라진다. 의사결정나무는 속성 하나씩 기준값으로 자르기만 해서 거의 필요 없다.
- **feature-wise (열 단위)**: StandardScaler(평균 0, 표준편차 1), MinMaxScaler(0~1), RobustScaler(중앙값 0, IQR 1), MaxAbsScaler(−1~1). 흔히 말하는 "스케일링"이 이쪽이다.
- **sample-wise (행 단위)**: Normalizer. 각 행을 벡터로 보고 L2 노름(원점에서의 거리)으로 나눠 길이를 1로 만든다. **크기는 사라지고 방향(속성 간 비율 패턴)만 남는다.**
- **L2 노름** = 제곱 → 합 → 루트 = 유클리드 길이. L1 노름은 절댓값의 합 = 맨해튼 거리.
- **거리 3형제**: 유클리드(직선), 맨해튼(블록), 코사인(각도). 텍스트 분석에서는 글 길이와 상관없이 단어 비율을 보는 **코사인 유사도**가 더 유용하다.
- **MaxAbsScaler**는 나누기만 해서 **0과 부호가 유지**된다. 그래서 0이 대부분인 희소 행렬에 쓴다. 다만 이상치에 민감하다.
- **단어 벡터화**: vocabulary 정의 → 원-핫 인코딩(단어장 크기 = 차원, 희소하고 낭비가 큼) → 임베딩(짧고 꽉 찬 벡터, 뜻이 비슷하면 방향도 비슷).
- **데이터 누수**: `fit`은 규칙(자) 만들기, `transform`은 그 자로 재기. test에는 `transform`만 쓴다.

```python
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled  = scaler.transform(X_test)   # test로 fit하면 누수
```

## 돌아보기

- **처음엔 "점 사이 거리를 코사인으로 재는 건가?"라고 생각했다.** 알고 보니 코사인은 거리가 아니라 방향을 비교하는 도구였다. 같은 거리 4라도 한쪽은 유사도 1, 다른 쪽은 −1이 나오는 예시를 보고 차이가 확실해졌다.
- **"정규화하면 속성 간 크기 차이가 사라진다"고 정리했다가 바로잡았다.** 사라지는 건 벡터 전체의 길이이고, 속성끼리의 비율은 오히려 그대로 남는다. 비슷해 보이는 문장 하나가 개념을 정반대로 만들 수 있어서, 앞으로 정리할 때 "무엇의" 크기인지 주어를 분명히 써야겠다.
- **몸무게 80, 키 182로 벡터 크기를 직접 계산해 봤다.** 숫자는 나오지만 kg과 cm를 섞은 값이라 의미가 없었다. 그래서 스케일링이 먼저라는 게 수업의 "연봉 1원 = 키 1cm?" 질문과 연결됐다.
- **헷갈리기 쉬운 용어 두 쌍을 구분했다.** 표준화(열 단위)와 정규화(행 단위)는 둘 다 "스케일링"이라 불려서 섞이기 쉽다. 원-핫 벡터에서 단어장 크기만큼 늘어나는 건 벡터의 "차원"이지 "크기(길이)"가 아니다.
- **MaxAbsScaler를 "왜 쓰지?" 하고 의문을 가진 덕분에 희소 행렬과 연결됐다.** 오후에 배운 원-핫 인코딩이 바로 그 희소 행렬이었다. 스케일러 선택이 데이터 모양(0이 많은가, 이상치가 많은가)에 따라 달라진다는 게 와닿았다.
- **슬라이드의 IQR 계산(6 − 2 = 4)과 sklearn 결과(3)가 달랐다.** 사분위수는 계산 방식이 여러 가지라서 그렇다. 수업 예시를 그대로 믿기보다 코드로 직접 확인해 보는 습관이 필요하다.
