## 오늘 배운 것

👉 [NumPy 배열 노트 (학습 아티팩트)](../artifacts/numpy-array-note.html)

- **ndarray**: 같은 타입만 담고, 여러 축으로 쌓고, 반복문 없이 통째로 계산(벡터화)하는 배열
- **shape / ndim / dtype**: 대괄호 겹 수 = 차원, shape는 바깥 → 안쪽 순서
- **arange vs range**: 둘 다 stop 미포함. arange는 실수 간격 OK, range는 정수만
- **연산**: `+ - * / // % **`는 전부 같은 자리끼리. `@`만 행렬 곱(곱해서 다 더하기)
- **인덱싱·슬라이싱**: 쉼표 = 축 구분. `[start:stop:step]`에서 stop만 미포함
- **조건 필터링**: 조건 → True/False 마스크 → True 칸만 통과. 여러 조건은 `&` + 괄호

## 돌아보기

### 가장 헷갈렸던 것: 어떤 숫자가 포함되고 어떤 숫자가 빠지는가

`arr[1:, 1]`의 뒤쪽 1이 포함인지 아닌지, `-1`이 어떨 땐 마지막 값이고 어떨 땐 마지막을 빼는지가 계속 헷갈렸다. 규칙을 하나씩 외우려니 더 꼬였다.

결국 판별법을 하나로 정리했다.

> 쉼표로 나눈 칸마다 콜론이 있는지만 본다. **콜론 바로 뒤에 붙은 숫자만 빠진다.**

이렇게 정리하니 `x[-1]`(포함), `x[:-1]`(빠짐), `x[-1:]`(포함)이 전부 같은 규칙 하나로 설명됐다. `x[::-1]`의 -1은 콜론 두 개 뒤, 즉 간격 자리라 "거꾸로 걷기"라는 것도 자리를 세면 바로 보인다.

### 숫자를 칸이 아니라 칼자국으로 보기

슬라이싱 숫자를 김밥 조각 사이 칼자국 번호로 보니, stop이 왜 안 들어가는지가 외우는 게 아니라 그냥 보이는 것이 됐다. 4번 칼자국은 4번 조각의 왼쪽 끝이라 4번 조각은 안 딸려온다. 읽는 설명으로는 이해가 안 됐는데, 직접 눌러서 조각이 올라오는 걸 보니 감이 왔다. 이해 안 될 때는 설명을 더 읽기보다 손으로 만져보는 게 빠르다.

### 질문이 질문을 불렀다

`arr[, -2:]`는 왜 안 되는지 물어보다가 쉼표 규칙이 NumPy가 아니라 파이썬 공통 규칙이라는 걸 알게 됐다. 대괄호 안에 쉼표를 쓰면 튜플, 대괄호를 또 쓰면 리스트(팬시 인덱싱)라는 데까지 이어졌다. 처음엔 사소해 보였던 "왜?"가 문법 전체를 이해하는 실마리가 됐다.

### 배운 게 어디에 쓰이는지 보이니 덜 지루했다

flatten을 왜 하는지 물었더니 신경망 입력층(FC 레이어)과 스케일링으로 이어졌고, `@` 행렬 곱이 FC 레이어 계산 그 자체(`x @ W + b`)라는 걸 알게 됐다. `X = data[:, :-1]`, `y = data[:, -1]`처럼 실무 단골 코드도 오늘 배운 슬라이싱 그대로였다. 문법이 실제 쓰임과 연결되니 기억에 훨씬 잘 남는다.

### 수업 자료도 의심해 보기

슬라이드의 `*` 예시는 `np.matrix`로 만들어져서, 실제로 돌리면 원소별 곱이 아니라 행렬 곱이 나온다. `range(0, 10, 1)`을 "0부터 10까지"라고 적은 것도 정확히는 0~9다. 자료를 그대로 믿기보다 직접 확인하는 습관이 필요하다.

## 느낀 점

아직까지 인덱싱과 슬라이싱이 많이 헷갈린다. 규칙은 이해했는데 막상 코드를 보면 바로 손이 안 나간다. 그래서 아티팩트 안의 게임(김밥 썰기, 바둑판 미션, 무한 주소 퀴즈)을 일주일 동안 쉬는 시간이나 버스로 오가는 길에 꾸준히 풀어서 몸에 익혀야겠다.
