1단계

스케일링이 왜 필요해? 🤔

스케일링은 데이터의 숫자 크기를 같은 기준에 맞게 조정하는 전처리예요. 한마디로 서로 다른 잣대를 하나의 잣대로 바꾸는 것이에요.

🏫 예시 1: 등수 정하기

수학은 100점 만점, 학점은 4.5점 만점이에요. 두 점수를 그냥 더해서 등수를 정하면 어떻게 될까요?

반 평균: 수학 70점(표준편차 10), 학점 3.5(표준편차 0.5)라고 가정했어요. 표준 점수 = (내 점수 − 평균) ÷ 표준편차.

💡 그냥 더하면 숫자가 큰 수학이 결과를 혼자 좌우해요. 학점 1점 차이는 거의 티도 안 나죠. 스케일링은 이런 숫자 크기 차이를 없애 줘요. 어떤 과목을 더 중요하게 볼지는 스케일링이 아니라 가중치로 따로 정해요.

📍 예시 2: 나랑 가장 비슷한 사람은? (거리 계산)

키(cm)와 연봉(원)으로 "나와 가장 가까운 사람"을 찾아볼게요. KNN이나 클러스터링이 실제로 하는 일이에요.

스케일링 후: 키 표준편차 10cm, 연봉 표준편차 1,000만 원으로 나눴다고 가정했어요.

🤖 어떤 모델이 스케일링을 꼭 필요로 할까?

모델필요?이유
KNN, 클러스터링(K-means), SVM꼭 필요거리로 판단하는 모델이라, 숫자가 큰 속성이 거리를 독차지해요.
선형 모델, 신경망권장학습이 더 안정적이고 빨라져요.
의사결정나무거의 불필요"연봉 > 2,000?"처럼 속성 하나씩 기준값으로 자르기만 해요. 단위가 바뀌면 기준값만 같이 바뀌고 결과는 똑같아요.
2단계

스케일러 5형제, 두 가족으로 나뉜다 👨‍👩‍👧‍👦

스케일러는 어느 방향으로 계산하느냐에 따라 두 가족으로 나뉘어요.

⬇️ feature-wise (열 단위)

나이, 연봉 같은 속성(열) 하나씩 평균·표준편차·최댓값·최솟값을 구해서 조정해요. 모든 피처를 비슷한 범위로 맞추는 것, 우리가 흔히 말하는 "스케일링"이에요.

👉 표준화, Min-Max, Robust, MaxAbs

➡️ sample-wise (행 단위)

데이터 한 줄(행) 전체를 하나의 화살표(벡터)로 보고, 그 길이를 1로 맞춰요. 크기는 뭉개지고 방향(비율 패턴)만 남아요.

👉 벡터 정규화 (Normalizer)

아래 표에서 버튼을 눌러 계산 방향을 비교해 보세요.

3단계

스케일러 실험실 🧪 (feature-wise 4형제)

열 하나에 들어 있는 숫자들을 4가지 스케일러로 동시에 바꿔 볼게요. 숫자를 직접 고치거나 버튼으로 골라 보세요.

😈 이상치 버튼을 눌러 보세요. Min-Max와 MaxAbs는 100 하나 때문에 나머지가 전부 0 근처로 찌그러져요. 표준화도 꽤 휘둘리고요. Robust만 비교적 멀쩡하죠? 중앙값과 IQR은 이상치에 거의 안 흔들리기 때문이에요.
🕳️ 희소 버튼을 눌러 보세요. 표준화는 평균을, Min-Max는 최솟값을 빼기 때문에 원래 0이던 칸이 0이 아닌 값으로 변해요(빨간 칸). Robust도 중앙값이 0이 아니면 마찬가지고요. MaxAbs는 나누기만 하니까 0 ÷ 6 = 0, 언제나 0이 그대로 남아요(초록 칸). 부호(+/−)도 유지돼요. 그래서 텍스트 단어 빈도표처럼 0이 대부분인 희소 행렬에 MaxAbs를 써요. 0이 사라지면 표 전체가 숫자로 꽉 차서 메모리가 폭발하거든요.
🔎 슬라이드의 IQR 계산과 숫자가 다르다면?

슬라이드는 1,2,3,4,5,6,100에서 IQR = 6 − 2 = 4라고 계산했어요. 그런데 사분위수는 계산 방식이 여러 가지예요. sklearn의 RobustScaler는 np.percentile(선형 보간)을 쓰기 때문에 Q1 = 2.5, Q3 = 5.5, IQR = 3이 나와요. 이 실험실도 sklearn 방식으로 계산해요. 개념(중앙값을 0, IQR을 1로 맞춘다)은 똑같아요.

4단계

L2 노름(norm)이 뭐야? 📏

노름(norm)은 어려운 말 같지만 사실 "화살표(벡터)의 길이를 재는 자"예요. 자를 어떻게 만드느냐에 따라 L1, L2 같은 종류가 있어요.

📐 L2 노름 = 직선 길이

각 숫자를 제곱 → 전부 더하기 → 루트. 피타고라스 정리 그대로예요. 원점에서 점까지의 직선 거리(유클리드 길이)예요.

‖x‖₂ = √(x₁² + x₂² + … + xₙ²)

🚕 L1 노름 = 블록 길이

각 숫자의 절댓값을 그냥 더하기. 바둑판 길을 따라 걷는 거리, 즉 맨해튼 거리예요.

‖x‖₁ = |x₁| + |x₂| + … + |xₙ|
🔤 기호 해독하기: ‖x‖₂
· x = 벡터 (데이터 한 줄, 예: (3, 4))
· ‖ ‖ (두 줄 막대) = "길이를 재라"
· ₂ (아래 2) = "L2 방식, 즉 제곱해서 재라"
→ 읽는 법: "x의 L2 노름" = "x의 유클리드 길이" = "원점에서 x까지의 거리"

🧮 L2 계산기: 한 단계씩 따라가기

숫자를 쉼표로 넣어 보세요. 2개면 평면, 3개면 공간, 더 많아도 계산법은 똑같아요!

💡 왜 제곱을 할까? 음수가 있어도 길이는 항상 양수여야 하니까요. (−3)² = 9처럼 제곱하면 부호가 사라져요. 마지막에 루트를 씌워서 원래 단위의 길이로 돌려놓는 거예요.
5단계

벡터 정규화 = 길이를 1로 줄이기 🔫

이제 L2 노름을 알았으니 정규화는 쉬워요. 각 숫자를 L2 노름으로 나누기, 끝!

정규화된 x = x ÷ ‖x‖₂

그러면 방향은 그대로, 길이만 1이 돼요. 아래 주황색 점을 끌어 보고, 정규화 광선을 쏴 보세요.

점의 위치(3, 4)
📏 L2 노름 (길이)5.00
정규화하면(0.60, 0.80)

📝 슬라이드 예제: X1 = (3, 4), X2 = (6, 8)

빈칸을 먼저 머릿속으로 채워 보고 버튼을 눌러 확인하세요.

유클리드 길이 (L2 노름)Normalizer 적용 후
X1 = (3, 4)??
X2 = (6, 8)??
🎯 X1과 X2는 길이가 2배 차이 나지만, 정규화하면 똑같은 점 (0.6, 0.8)이 돼요! 둘 다 3:4 비율, 즉 같은 방향이니까요. 정규화된 점은 모두 반지름 1인 원(그림의 초록 점선) 위에 모여요. 3개 숫자라면 반지름 1인 공 표면 위에요. 슬라이드의 (0.6, 0.6, 0.529)도 0.6² + 0.6² + 0.529² ≈ 1이라 공 표면 위의 점이에요.
# 수업 코드 (2.06.스케일링.Normalizer.ipynb) 핵심만
from sklearn.preprocessing import Normalizer
X = np.array([[3, 4], [6, 8]])
X_normalized = Normalizer(norm='l2').transform(X)
# → [[0.6, 0.8], [0.6, 0.8]]

⚠️ 헷갈리기 쉬운 점: "속성끼리의 차이"는 사라지지 않아요! (3, 4) → (0.6, 0.8)에서도 비율 3:4는 그대로예요. 사라지는 건 화살표 전체의 길이뿐이에요.

레모네이드로 이해하는 코사인 유사도 🍋

레모네이드 한 잔을 벡터 (레몬, 설탕)으로 써 봐요. 작은 컵 (1, 2)와 대형 물통 (5, 10)은 양은 5배 차이지만 맛은 똑같아요. 비율이 1:2로 같으니까요.

🥤 크기 = 얼마나 많이 만들었나 (양)  ·  😋 방향 = 레몬:설탕 비율 (맛)

🥤 컵 A

🪣 컵 B

📏 양 차이 (유클리드 거리)4.47
😋 맛 일치도 (코사인 유사도)100%
📄 텍스트 분석에서는 방향(코사인)이 더 유용해요. 문서를 단어 빈도 벡터로 바꾸면, 긴 글은 모든 숫자가 커져서 화살표가 길어질 뿐이에요. 글이 길든 짧든 어떤 단어 위주인지(비율 패턴)가 같으면 같은 주제죠. 그래서 TF-IDF, 문서 유사도, 검색, 추천에서는 정규화 후 코사인 유사도로 비교해요.
6½단계

단어도 벡터로 바꿔야 해요 🔤➡️🔢

컴퓨터는 글자를 이해하지 못하고 숫자만 계산할 수 있어요. 그래서 단어나 글자도 벡터(숫자 묶음)로 바꿔야 모델링을 할 수 있어요.

📖 1. 먼저 단어장(vocabulary)을 정한다

언어 모델이 가장 먼저 정의하는 것이 vocabulary, 즉 "우리 모델이 아는 단어 목록"이에요. 단어장에 A, B, C 세 단어만 있다고 해 봐요.

☝️ 2. 원-핫 인코딩: 자기 자리만 1

단어A 자리B 자리C 자리
A100
B010
C001
🔤 용어 구분: 여기서 숫자의 개수(3개)는 벡터의 차원이에요. 단어장 크기 = 벡터 차원이죠. 앞에서 배운 벡터의 크기(길이, L2 노름)와는 다른 말이에요. 원-핫 벡터는 차원이 몇이든 길이는 항상 √1 = 1이에요.

문제는 단어장이 커질 때예요. 슬라이더를 움직여 보세요.

🕳️ 단어장이 5만 개면 단어 하나를 숫자 5만 개로 쓰는데, 그중 49,999개가 0이에요. 이렇게 0이 대부분인 행렬을 희소 행렬(sparse matrix)이라고 해요. 3단계의 MaxAbsScaler가 아끼던 바로 그 희소 행렬이에요! 자원 낭비가 심하고, 모든 단어 사이의 각도가 90°라 코사인 유사도가 전부 0이에요. "고양이"와 "강아지"가 비슷하다는 걸 전혀 표현하지 못해요.

9단계

데이터 누수 조심! fit과 transform 🚰

데이터 누수(Data Leakage)란 실제 예측할 때는 알 수 없는 정보, 특히 평가(test) 데이터의 정보가 학습이나 전처리에 몰래 섞여 들어가는 거예요.

📐 fit = 자(규칙) 만들기

데이터를 보고 평균, 표준편차, 최솟값·최댓값 같은 기준을 계산해서 저장해요.

📏 transform = 그 자로 재기

이미 만든 기준으로 값을 변환만 해요. 새로 계산하지 않아요.

🎒 비유: 시험 전에 기말고사 문제를 미리 보고 공부하면 점수는 잘 나오지만, 진짜 실력은 아니죠? test 데이터로 fit하는 것도 똑같아요. test의 평균을 미리 알아 버리면 모델 성능이 실제보다 좋게 부풀려져요.
# ✅ 올바른 방법: train으로 자를 만들고, test는 그 자로 재기만
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled  = scaler.transform(X_test)

# ❌ 누수: test로 자를 또 만들어 버림
X_test_scaled  = scaler.fit_transform(X_test)
스케일러fit할 때 저장하는 것 (자의 눈금)
StandardScalermean_ (평균), scale_ (표준편차)
MinMaxScalerdata_min_, data_max_
RobustScalercenter_ (중앙값), scale_ (IQR)

참고로 Normalizer는 행마다 자기 길이로 나누기만 해서 저장할 기준이 없어요. 그래서 누수 걱정이 거의 없어요.

스케일러방향하는 일이상치주 사용처
StandardScaler⬇️ 열평균 0, 표준편차 1민감한 편대부분의 기본값 (선형 모델, SVM, 신경망)
MinMaxScaler⬇️ 열0~1 범위취약범위를 고정하고 싶을 때, 이미지 픽셀
RobustScaler⬇️ 열중앙값 0, IQR 1강함이상치가 많을 때
MaxAbsScaler⬇️ 열−1~1, 0과 부호 유지민감희소 행렬 (0이 많은 데이터)
Normalizer➡️ 행각 행의 L2 노름을 1로—코사인 유사도, TF-IDF, 텍스트 마이닝
🧭 판단 질문 두 개:
1. 속성마다 단위가 달라서 맞춰야 해? → 열 단위 스케일러 (이상치 많으면 Robust, 0이 많으면 MaxAbs)
2. 크기는 상관없고 비율 패턴(방향)만 비교하고 싶어? → 행 단위 Normalizer + 코사인
