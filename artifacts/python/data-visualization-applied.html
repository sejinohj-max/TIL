지퍼와 번호표: zip · enumerate · 오차

predicted = [115, 242, 176, 148, 115, 209, 185, 256, 129, 195]
error = [(x - y) for x, y in zip(actual, predicted)]
xs = [i for i, _ in enumerate(error)]

여기서 꼭 알아야 할 6가지

  1. zip(a, b)는 두 리스트에서 같은 번호끼리 하나씩 꺼내 (a[i], b[i]) 짝으로 내줘요. 지퍼 이빨이 맞물리는 것처럼.
  2. for x, y in …는 짝을 받자마자 두 이름에 나눠 담는 것(언패킹)이에요. 1장의 j[0], j[1]을 이름 두 개로 바로 받는 방식이에요.
  3. 여기서 x, y는 그래프 축이 아니에요. 그냥 실제값, 예측값에 붙인 이름이라 a, p라고 써도 똑같이 돌아가요.
  4. error = 실제 − 예측. 음수면 예측이 실제보다 높았다(과대예측), 양수면 낮았다는 뜻이에요.
  5. enumerate(리스트)는 값마다 번호표를 붙여 (번호, 값)으로 내줘요. 번호는 0부터.
  6. _(밑줄)은 "받긴 받는데 안 쓸 거야"라는 표시용 이름이에요. 그래서 xs에는 번호만 남아 [0, 1, …, 9]. x축 자리표예요.

zip: 두 줄을 지퍼처럼 맞물리기

_ 는 특별한 문법이 아니에요

평범한 변수 이름이고 값도 실제로 들어가요(마지막엔 3). "이건 안 쓴다"고 읽는 사람에게 알려주는 관례예요.

_ (밑줄) 완전 정복

_는 특별한 문법이 아니라 평범한 변수 이름이에요. 이름을 _로 지으면 "이 값은 받기만 하고 안 쓸 거야"라는 신호가 돼요. 짝을 받으려면 자리가 두 개 필요한데, 그중 안 쓸 자리에 붙이는 버림통 이름표예요.

stores.iterrows() 는 한 바퀴마다 (행 번호, 그 행 전체) 짝을 내줘요 · 받는 방법을 골라 보세요

for _ 와 case _ 는 다른 _ 예요
      
for _, row의 _는 평범한 변수라서 값이 담겨요. case _의 _는 문법이라서 값이 안 담겨요. "아무거나 맞음" 표시일 뿐이에요. case (3, _)처럼 짝의 한 자리만 "아무거나"로 둘 수도 있어요.

    
case _ vs case other

match 5:
    case other:      # 아무거나 맞고
        print(other) # other에 5가 담김

      
값이 필요 없으면 case _:, 필요하면 이름을 써요. 둘 다 맨 마지막에만 둘 수 있고, 중간에 두면 "아래 칸들이 절대 실행 안 된다"는 에러가 나요.

                               stratify=df_study["survived"], random_state=42)
